The first published release of Stock Indicators: technical-indicator monitoring you run yourself.
Combine indicators into rule trees, bind a rule to an instrument and a time frame, and get a
notification the moment the condition fires - with the chart fragment that triggered it. One
installation, one operator: no accounts, no billing, no telemetry, and no market data ships with it,
because every source is connected with your own key.

## Run it

```bash
git clone https://github.com/Drenalol/StockIndicators && cd StockIndicators/packaging
cp .env.example .env          # then set SI_PASSWORD (and POSTGRES_PASSWORD)
docker compose up -d
```

Open http://localhost:8080, sign in with that password, and connect your sources under
**Settings -> Providers**: every card has a connection test, and an enablement applies after a
restart. **Settings -> About** shows the version and build id of the instance you are looking at.

Nothing is required beyond the password to reach a running instance, and a fresh one tells you what
it still needs. Redis is optional: `docker compose --profile redis up -d`.

## What is inside

- **35 indicators**: moving averages (SMA, EMA, WMA, HMA, KAMA, VWMA), RSI, MACD, Bollinger Bands,
  Stochastic and StochRSI, ADX, ATR, CCI, CMO, Chandelier Exit, Donchian, Keltner, Ichimoku, MFI,
  OBV, PSAR, SuperTrend, Trailing Stop, TSI, VWAP, Vortex, Williams %R, gap / round-price /
  52-week-high-low detectors, volume and price change.
- **Rules** as an AND/OR tree of conditions over one or more indicators of one or more instruments,
  with ready-made presets for the common shapes.
- **Subscriptions** with a cooldown, trading-session awareness (MOEX and US sessions with holidays,
  pre/post/overnight) and an unread history.
- **Trigger history with charts**: every alert keeps the candle it saw and the detection moment, and
  the notification carries a rendered chart with the marker on the candle that fired.
- **Channels**: Telegram (a full bot with forms), Web Push, Discord, WhatsApp, SMTP email and a
  generic webhook, with per-subscription templates and variables.
- **Nine interface languages**: en, ru, be, uk, de, es, fr, it, pt-BR.
- A public indicator catalog with an example chart and one-tap rule presets per indicator, which
  runs without a database when you publish only the marketing surface.

## Bring your own data

Tinkoff Invest API (Russian market), Alpaca (US equities, paper keys are enough), Binance (crypto),
BusinessQuant (EOD and intraday for US/global equities), plus Yahoo Finance as an instrument-metadata
enricher. Keys live in your database, entered through the UI; environment variables stay a fallback.
Each provider's own terms decide what you may do with the data you pull with your own key - read
[docs/DATA_SOURCES.md](https://github.com/Drenalol/StockIndicators/blob/main/docs/DATA_SOURCES.md) before exposing an instance to other
people.

## Image

The image is one origin: the React frontend and the .NET API behind it, the alert scheduler, and the
headless Chromium that renders alert pictures. `linux/amd64` and `linux/arm64` are in the same
manifest, so `docker compose up -d` works on a desktop, a small server or a Pi. PostgreSQL 14+ is
required and the compose stack brings its own; migrations are applied at startup.

`SEO_BASE_URL` is baked at build time into the static link-preview pages, so the published image
carries none: canonical, `og:url` and `sitemap.xml` stay relative. That is right for a LAN install;
publishing behind a domain means building the image once with that build arg, which is also the
route for a custom Chromium or font set.

## Upgrading

```bash
docker compose pull && docker compose up -d
```

`SI_IMAGE_TAG=latest` follows the releases; set it to a version (`SI_IMAGE_TAG=1.0.0`) to pin the
instance. Set `SI_PASSWORD` in `packaging/.env` before exposing anything beyond localhost, and change
`POSTGRES_PASSWORD` too. The database is a volume: `docker compose down -v` deletes it.
